# Phase 3 gold-set rating guidelines

How the Phase 3 severity gold standard is made: **visual severity
estimation** of the main leaf, aided by standard area diagrams, in the
rating tool (`python -m src.severity.rating_tool`). These definitions are
authoritative for that tool and for anyone checking the ratings.

**History:** the gold standard was first planned as hand-drawn pixel masks
(leaf + lesion). Two pilots of the mask tool failed to produce usable masks
(`experiments/LOG.md`, 2026-11-01 and 2026-11-02), so on 2026-11-02 it was
replaced by visual rating. The mask tool (`src/severity/annotation_tool.py`)
is kept in the repo but retired.

## Why visual rating

Rating disease severity by eye as "% of leaf area affected" is the standard
way severity is measured in plant pathology. Standard area diagrams (SADs),
reference drawings of leaves with known % affected, are the usual aid for
making those estimates more accurate and consistent. TODO: cite a source
for both claims before the report (candidate to check: Del Ponte et al.,
2017, a review of SADs in *Phytopathology*; **not yet verified**, don't
cite until checked). Known weakness: unaided raters tend to overestimate
low severities. The SADs are there to reduce this, and the self-consistency
check measures how repeatable the ratings are.

## Independence from the pipeline (read this first)

The rating tool shows **only the photo**. No PlantSeg mask, no model
prediction, no SAM output and no refinement result is ever displayed, before
or after rating. If any of these were visible, the gold rating could lean
toward the method it's supposed to test. The SADs are synthetic
(generated by `src/severity/area_diagrams.py`) and don't use any pipeline
code or thresholds.

## Tuning set vs. gold test set

- **Tuning set**: 3 images per disease (15 total), drawn from the **val**
  split, non-disputed `close_up` only (same eligibility as gold, so tuning
  matches the conditions it's tested under). Used only to tune refinement
  thresholds and SAM prompting during Phase 3 development. Never used to
  report final numbers.
- **Gold test set**: drawn from the **test** split, **non-disputed,
  `close_up` only**: **11 images each** for stripe rust, powdery mildew,
  septoria blotch and bacterial leaf streak, plus **all 10** eligible wheat
  leaf rust images, **54 total**. Rated once, evaluated once, at the end
  of Phase 3 - no iterating on the refinement pipeline against it
  afterward. If the pipeline needs more tuning after seeing gold-set
  results, that's a new tuning round against the tuning set, not a second
  look at gold.
  - Why leaf rust gets 10: that is every eligible test image (counted from
    the latest tag per image in `data/processed/wheat_tags.csv`, 2026-11-01:
    stripe rust 43, powdery mildew 31, septoria 27, bacterial leaf streak 19,
    leaf rust 10). Filling the gap with disputed or `wide` images would
    break eligibility. Any leaf rust image that has to be skipped can't be
    replaced, so that class may end up below 10.
  - **Leaf rust is flagged as low-n in every table** that reports it.

- **Pilot set**: 5 images, one per disease, from the **training** split
  (non-disputed `close_up`). Used only to time the workflow and shake out
  tool problems. Taken from train so the pilot uses up no tuning or gold
  images. The rating pilot **skips images already seen in the mask-tool
  pilots** (any pilot image in `data/annotations/annotation_log.csv`), so
  its timings aren't sped up by images the rater already knows.

The tuning and gold queues are the same frozen files as before
(`data/annotations/queues/<set>.csv`). Nothing from the mask tool was
saved for tuning or gold, so they start fresh.

### How images are chosen (no cherry-picking)

1. List every eligible image for the disease and split, then shuffle with
   the config seed. The tool works through them in that order. The order is
   **frozen** to `data/annotations/queues/<set>.csv` the first time the
   tool starts, so later re-tags can't reshuffle it (a seeded shuffle of a
   shorter list is a completely different order), and re-tagged images
   stay in the queue and are counted as skipped.
2. Rate in that order. **You may skip an image only for one of these
   reasons**, recorded in the rating log with the image name:
   - no single main leaf can be identified (see below);
   - the main leaf is too blurred to tell lesions from healthy tissue;
   - the image isn't actually wheat leaf disease (should already have been
     caught by tagging, but log it if it slips through);
   - the image is not a real photo (illustration, drawing, diagram) that
     was mis-tagged `close_up`;
   - **collage / multi-panel image** (several photos combined into one
     image).
   The last two reasons **also re-tag the image to `non_photo` in
   `data/processed/wheat_tags.csv`** (new row, `tag_source =
   human_annotation`, `original_tag` and `disputed` carried forward
   unchanged), so it drops out of every `close_up` subset.
   "Looks hard" or "the model will probably get this wrong" is **not** a
   reason to skip.
3. Stop when the quota is reached. Skipped images are reported alongside
   the results (count and reasons), since heavy skipping would bias the
   gold set toward easy images.

## Main-leaf rule

Severity is measured on **the main leaf**: the leaf with the most visible
disease in the photo. This applies everywhere: the rating (you rate only
the main leaf, not the whole photo) and the pipeline (every method's
severity is computed on the main leaf found from your click, see
*Evaluation plan*).

If it's ambiguous which leaf has the most visible disease (close call
between two leaves), pick the one that is **more fully in frame**, and
note the image name - this should be rare at `close_up` framing, where one
leaf usually dominates the frame already.

**Only lesions on the main leaf count.** Disease on other leaves, stems or
the background is ignored, even if it's obvious.

## What counts as a lesion, per disease

**wheat stripe rust / wheat leaf rust** - orange or orange-brown pustules.
Count the pustules themselves; don't include unaffected green tissue
between them just because it's "nearby."

**wheat septoria blotch** - brown necrotic blotches, often with small dark
dots (pycnidia) visible within them. Count the necrotic area including the
dots.

**wheat powdery mildew** - the white/grayish-white powdery coating itself.
Don't count green tissue just because it's under or near a coated patch.

**wheat bacterial leaf streak (black chaff)** - brown streaks, or
earlier-stage water-soaked (darker, slightly glossy/translucent)
streaking. This is the hardest of the four to call confidently - if a
streak's edge is ambiguous between "water-soaked" and "just slightly
shaded healthy tissue," err toward the tighter/smaller interpretation
rather than the generous one, so the gold set doesn't quietly inflate this
class's severity.

## Chlorotic (yellow) tissue - PLACEHOLDER rule

**Count chlorotic/yellow tissue only when it directly touches or
surrounds a lesion.** Don't count isolated yellowing elsewhere on the leaf
(common causes unrelated to this disease: natural senescence, nutrient
deficiency, heat/drought stress) - only the chlorotic halo immediately
adjacent to a real lesion counts.

**This rule is not validated against any agronomy source** (same caveat as
the severity thresholds and decision mapping in `configs/config.yaml`). It
is a judgment call, reasoned from the general plant-pathology practice of
scoring a lesion's chlorotic halo as part of the affected area while
excluding unrelated leaf yellowing. Revisit if a better source turns up.

**How the ratings were actually made (recorded 2026-11-14, Adrija's statement
after the gold evaluation):** when rating the tuning and gold images, the rater
**included discoloured tissue** in the severity, and did not restrict the count
to clear lesions. This was asked because, on three tuning photos, the
discoloured area looked much larger than the rating to the assistant that built
the method (`report/figures/pregold_round2/`). With this answer the gap on those
photos is not explained by a narrower rating definition; it stays an open
disagreement between the rating and the method (and the reader of the
figures). No rating was changed, and no extra gold analysis was run.

## The click: marking the main leaf

Click **once, on the main leaf**, on clearly visible leaf tissue: roughly
in the middle of the leaf's width, away from its edges, and preferably on
healthy-looking tissue rather than inside a big lesion. Clicking again
moves the point. The point's pixel coordinates (original image resolution)
are stored. It's the only prompt SAM 2 gets when the evaluation finds the
leaf, so a click near an edge or on a lesion risks SAM returning the wrong
object.

## Rating severity

**Severity % = share of the main leaf's visible area covered by lesions**
(per the definitions above), from 0 to 100.

- **Visible area only.** Parts of the leaf hidden behind another leaf, a
  stem or a hand don't count. If the leaf runs off the frame, rate the
  visible part (a known limitation, to be stated in the report).
- **Use the reference panel.** The SADs show leaves with exactly 1, 2, 5,
  10, 20, 35, 50 and 75% affected, in rust-, blotch- and mildew-like
  styles (the tool opens the style that matches the image's disease). Find
  the two diagrams your leaf falls between, then pick a value between them.
  Don't snap to the diagram values.
- **Zoom in** (scroll) before rating small pustules or pycnidia. Below 5%,
  rate to the nearest 0.5%. Above that, the nearest 1% is enough.
- **Ratings above 75%** (the highest diagram) need a second Save of the
  same value: the tool asks you to check that only lesion area was counted.
- **0% is allowed** if no lesion is visible on the main leaf. Note it.
- Small photos are enlarged on screen to fill the photo area (display
  only: the stored click is always in original-image pixels).
- There's no time cap. Don't count pustules one by one. Look, compare with
  the diagrams, and decide.
- Never look up the image's PlantSeg mask or any model output before or
  during rating.

## Rater training (practice, before rating)

The tool's **Rater training** tab shows 15 synthetic leaves drawn like the
SADs, with hidden, exactly known severity (0.5-60%, drawn log-uniformly so
low severities get as much practice as high ones; 5 each in rust, blotch
and mildew style). After each rating it shows the true value and your
error. At the end it shows your mean absolute error and whether you over-
or underestimate on average. Repeat with a fresh set as often as you like.
Results are appended to `report/tables/rater_training.md`. Training never
reads or writes the pilot, tuning, gold or recheck logs, and it is
practice only: training results are not part of any evaluation. Caveat:
synthetic leaves are flat, evenly lit and high-contrast, so error on real
photos is likely higher than training error. Training shows the direction
of your bias; it doesn't estimate your accuracy on real photos.

## Rating log

`data/annotations/rating_log.csv`, append-only (the latest row per set +
image wins). Columns: image name, split, disease, set
(pilot/tuning/gold/recheck), rater, status (done/skipped), skip reason,
click x and y (original-resolution pixels) and image width and height,
severity %, time per image (seconds from image load to save or skip,
excluding paused time), notes, timestamp. Time per image feeds the pilot
report.

The log and the frozen queues (`data/annotations/queues/*.csv`) are tracked
in git. **Commit the rating log after every rating session.**

**Gold ratings are locked (2026-11-04, git tag `gold-v1`).** No gold rating or
skip may be added or changed from now on. Only the logged recheck is open, and
it writes separate `recheck` rows. The rating tool refuses gold saves and skips
(`annotation.gold_locked`), and a test compares the gold rows with
`annotation.gold_sha256`.

**Gold exclusions.** Images listed in `annotation.gold_exclude` are left out of
every evaluation metric. Their ratings stay unchanged in the locked log (the
lock is on the rows, and an exclusion doesn't touch them). The reason for each
is in `experiments/LOG.md`, and the count and names are reported with the
results. Currently one image:
`wheat_bacterial_leaf_streak_(black_chaff)_black_chaff (3).jpg`, a photo of
detached spikes with no leaf, so the main-leaf rule can't apply (decided
2026-11-11, before any method existed).

**Tuning exclusions.** Images listed in `annotation.tuning_exclude` must not be
used for tuning. Their ratings stay unchanged in the log, and their slots aren't
refilled. The reason for each is in `experiments/LOG.md`. Three are excluded,
which leaves 12 tuning images: stripe rust 2, leaf rust 2, powdery mildew 3,
septoria blotch 3, bacterial leaf streak 2.

## Self-consistency check (after the gold set is finished)

Once all gold images are rated, the tool picks **15 gold images at random**
(seeded) and has you re-rate them **blind**: your first rating and click
are never shown, and the image isn't marked as already done. Re-ratings
are saved separately (set `recheck`) and never overwrite the gold ratings.
We report the **mean absolute difference between your two ratings** (in
percentage points), with a bootstrap 95% CI and the per-image differences.
This is a rough floor on how precisely "true" severity can be measured
here: a method whose error vs gold is about that size is as close as a
second look by the same rater. With one rater and n = 15 this is a
repeatability check, not an inter-rater agreement study, and it'll be
described that way. Recheck images can't be skipped. Do the recheck in a
separate session from the end of the gold set, so the first ratings are
less fresh in memory.

**Result (2026-11-09, `report/tables/recheck_agreement.md`):** mean absolute
difference 3.40 points (bootstrap 95% CI 1.80 to 5.17), Lin's CCC -0.08 (95% CI
-0.38 to 0.17), same placeholder severity level 7 / 15. The **resolution
limit** in the evaluation plan below is the same statistic on the 14 of these
images that stay in evaluation.

## Wrong-leaf check (after the gold ratings are locked)

SAM 2 finds the leaf from your click, and nobody sees that leaf during
rating (showing it would break independence). A wrong SAM leaf would put
every method's severity on the wrong object. So, **once all gold ratings
(and the recheck) are finished and locked**, every gold image is shown
once more with **only your click and SAM's leaf outline**: no severity
values (yours or any method's), no lesion masks, no PlantSeg mask. You mark
each one **correct leaf**, **wrong leaf** or **not a leaf**: wrong if the
outline is mostly on a different object than the leaf you clicked, or covers
several leaves or background; not a leaf if the object you clicked is a
spike, stem or anything else that isn't a leaf, however good the outline is.
The **not a leaf** option was added on 2026-11-11, before the check was
built or run, so the rule behind the gold exclusion (spikes violate the
main-leaf rule) is applied to every gold image the same way.

**Partial-leaf rule (Adrija, 2026-11-14).** An outline counts as **correct
only if it covers roughly three-quarters or more of the clicked leaf's
visible area**. Less than that is **wrong leaf**. The amount is judged by
eye from the overlay. This rule was added during the check, after the first
pass showed the original wording didn't settle outlines that cover only part
of the leaf, and before any severity was computed on gold. It was re-applied
to the five outlines the first pass had flagged as partial (4 became wrong, 1
stayed correct; reasons in `report/tables/leaf_check_notes.csv`).

**Who judged (2026-11-14).** The verdicts were made by Claude (AI) from the
overlays, then checked on a contact sheet by Adrija, who set the
partial-leaf rule and accepted the remaining verdicts. The check is locked
(`annotation.leaf_check_locked`, tag `leaf-check-v1`). After the check, two
collage images and one duplicate photo were also excluded
(`annotation.gold_exclude`). The two collages were re-tagged `non_photo`
the same day by Adrija's decision (`tag_source = human_decision`,
`original_tag` kept), which takes them out of the Phase 2 test set (123 to
121 images).

- The SAM leaf is produced by the evaluation's fixed rule (see below),
  never re-prompted or edited in this step. If it's wrong, the image is
  excluded. It is not fixed.
- Ratings can't be changed during or after this check.
- Results go to `data/annotations/leaf_check_log.csv` (image name, verdict,
  rater, timestamp).

**Fixed rule (decided 2026-11-02, before rating):** wrong-leaf images are
excluded from evaluation, and their count is reported. Not-a-leaf images are
excluded the same way and counted separately (2026-11-11).

## Evaluation plan (gold set)

**Role of this evaluation (changed 2026-11-11, before any method existed).**
Severity accuracy against gold is a **secondary** result. The project's
**primary** contribution is Phase 4: how much a model's severity estimate
shifts between a clean photo and its corrupted copy, and how often that
flips the decision. Those compare the model with itself, so they don't
need gold and aren't limited by rating noise.

**Resolution limit: 3.64 points** (decided 2026-11-11). This is the rater's
own test-retest noise: the mean absolute difference between gold and recheck
on the 14 recheck images that remain after the gold exclusion (95% CI 2.04 to
5.46), with Lin's CCC of about 0 (-0.07). On all 15 recheck images it is 3.40.
Two rules follow:
- This figure is **reported next to every method result** against gold.
- **No claim that one method is better than another is made when their MAE
  differs by less than the resolution limit**, whatever the confidence
  intervals say. Such results are reported as "not distinguishable at the
  gold standard's resolution".

Because CCC is about 0 within the 3-17% range the recheck covered, gold can't
be trusted to rank images within that range. Whether it separates low from
clearly high severity is untested: no recheck image was rated above 16.5%.

**Leaf mask:** for each gold image, SAM 2 (the config's `sam2` model) is
prompted with **only the stored click** (one positive point). SAM 2 returns
3 candidate masks, and the leaf is the **highest-scoring candidate that
covers at least 2% of the image**, or the largest candidate if none does
(`sam2.leaf_rule: min_area`, `src/severity/leaf_mask.py`). This rule and the
tiny model were **frozen on 2026-11-11**, chosen on the tuning set only and
before any gold image was processed (`report/tables/leaf_rule_review.md`). It
replaced the first rule (highest-scoring candidate), which often returned a
fragment of the leaf. This SAM leaf is
used for **every** method, so all methods are compared on the same leaf.

**Methods**, each giving `severity = lesion pixels on leaf / leaf pixels`,
reported as %:
- **A:** PlantSeg's own infected-region outline, clipped to the SAM leaf.
- **B:** the Phase 2 model's predicted infected region, clipped to the SAM
  leaf.
- **C:** the refined lesions (Phase 3 refinement), on the SAM leaf.

**Metrics** (method severity vs your rating):
- **Main gold metric: pooled severity MAE** (percentage points) over all rated gold
  images (all diseases together), with a bootstrap 95% CI.
- **Secondary:** per-disease severity MAE with bootstrap CIs. Leaf rust is
  flagged low-n.
- **Secondary, by gold rating band:** severity MAE with bootstrap CIs, reported
  separately for **low (< 10%), medium (10% to < 20%) and high (≥ 20%)** gold
  ratings. Before wrong-leaf exclusions the bands hold 38, 7 and 8 images (39, 7
  and 8 before the 2026-11-11 gold exclusion, which removed one 5.5% image). The
  **high band is flagged low-n** in every table, and the medium band is just as
  small. These bands are for reporting error only; they aren't the config's
  placeholder severity levels. Added 2026-11-04, after the ratings were finished
  and before any method was scored against them.
- **Severity-level agreement:** both the rating and the method severity
  are binned with the config's severity thresholds, and we report the
  share of images where the levels match, plus the confusion matrix.
- **Decision agreement:** the same, after mapping levels to decisions with
  the config's decision mapping. Thresholds and mapping are
  **PLACEHOLDERS** (not validated against an agronomy source) and are
  marked as such in every table.
- **Skipped images:** count and reasons reported.
- **Self-consistency:** the 15-image re-rating result above, reported
  next to the methods' MAE as the resolution limit (see the top of this
  section).
- **Gold exclusions:** images in `annotation.gold_exclude` are excluded
  from every metric, and their count and names are reported. With the one
  current exclusion the evaluated set is at most 53 images (bacterial leaf
  streak 10), before wrong-leaf exclusions.
- **Wrong-leaf exclusions:** gold images marked "wrong leaf" in the
  wrong-leaf check (below) are **excluded from every metric**. The count
  (per disease and in total) and the image names are reported. This rule
  was fixed on 2026-11-02, before any gold image was rated, and is not
  revisited after seeing results.
- **Phase 2 knock-on:** once the gold set is finished, if any **test**
  images were re-tagged `non_photo`, the Phase 2 test set (non-disputed
  `close_up`) has changed. Re-run the Phase 2 test evaluation for both
  baselines and note the change (old vs new n and metrics) in
  `report/tables/baselines.md`. Training-split re-tags (e.g. from the
  pilot) are logged in `experiments/LOG.md` but don't trigger retraining.
